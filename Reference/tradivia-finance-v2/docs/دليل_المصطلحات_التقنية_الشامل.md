# دليل المصطلحات التقنية الشامل

> **الغرض من هذا الدليل:** أن تفهم عالم البرمجة الحديثة، السيرفرات، قواعد البيانات، والسحابة — بعمق وبوضوح — حتى تتحدث مع المبرمجين والعملاء بثقة، وتتخذ قرارات تقنية صحيحة لمشاريع UNI GATE و TRADIVIA.
>
> **من أين أنت؟** Google Apps Script + Google Sheets + HTML بسيط.  
> **إلى أين تذهب؟** TypeScript + NestJS + Next.js + PostgreSQL + VPS/Cloud.

# الجزء الأول: الصورة الكبيرة

## 1. كيف يعمل أي نظام ويب؟

عندما يفتح العميل نظام TRADIVIA من المتصفح، يحدث التالي:

```
العميل (متصفح Chrome)
        │
        │ ① يطلب صفحة أو بيانات عبر الإنترنت
        ▼
السيرفر (جهاز في السحابة يعمل 24/7)
        │
        ├── ② يعرض الواجهة (HTML/CSS/JS أو React)
        ├── ③ ينفّذ المنطق (حساب أرصدة، موافقات، صلاحيات)
        └── ④ يقرأ/يكتب في قاعدة البيانات
                │
                ▼
        قاعدة البيانات (PostgreSQL)
        (الجداول: incomes, outcomes, employees...)
```

### مقارنة مع Google Apps Script

| الجزء | Google Apps Script | النظام الجديد |
|-------|-------------------|---------------|
| الواجهة | HTML في `HtmlService` | Next.js (React) |
| المنطق | `Code.js` على خوادم Google | NestJS على سيرفرك |
| البيانات | Google Sheets | PostgreSQL |
| المرفقات | Google Drive | تخزين ملفات (S3/R2/محلي) |
| الرابط | `script.google.com/...` | `https://finance.tradivia.com` |
| من يملك البنية؟ | Google | أنت (UNI GATE) |

**الفائدة:** تحكم كامل، لا حدود Google، محاسبة حقيقية، آلاف العملاء لاحقاً.

## 2. Local مقابل Production — أهم مفهوم

### Local (محلي / التطوير)

- التطبيق يعمل **على جهازك** فقط.
- الرابط: `http://localhost:3000`
- **لا أحد** من الإنترنت يصل إليه.
- قاعدة البيانات على جهازك (أو Docker محلي).
- **الغرض:** البرمجة والاختبار — كسر الأشياء بأمان.

**تشبيه:** مطبخ تجرب فيه الأطباق قبل فتح المطعم.

### Production (إنتاج / مرفوع / Live)

- التطبيق على **سيرفر** متصل بالإنترنت 24/7.
- الرابط: `https://app.unigate.com`
- **العملاء** يستخدمونه من أي مكان.
- **الغرض:** العمل الحقيقي.

**تشبيه:** المطعم المفتوح للزبائن.

### Staging (تجريبي قبل الإنتاج)

- نسخة شبه الإنتاج لاختبار نهائي.
- الرابط: `https://staging.unigate.com`
- الفريق فقط يصل إليه.
- **الغرض:** التأكد قبل إطلاق تحديث للعملاء.

### Development / Dev

- مرادف لـ Local في أغلب الفرق.

### ملخص سريع

| المصطلح | أين؟ | من يصل؟ | متى؟ |
|---------|------|---------|------|
| Local / Dev | جهازك | أنت | أثناء البرمجة |
| Staging | سيرفر تجريبي | الفريق | قبل الإطلاق |
| Production | سيرفر حقيقي | العملاء | دائماً |

**Google Apps Script:** نظامك الحالي **Production على سحابة Google** — العميل يفتحه من الإنترنت، لكن الكود والبيانات تحت سيطرة Google وليست تحت سيطرتك الكاملة.

# الجزء الثاني: البنية التحتية (Infrastructure)

## 3. السيرفر (Server)

### التعريف

جهاز كمبيوتر (فيزيائي أو افتراضي) قوي، متصل بالإنترنت، يعمل بدون توقف، مخصص لتشغيل تطبيقاتك.

### أنواع السيرفرات

| النوع | الشرح | متى تستخدمه |
|-------|--------|-------------|
| **Physical Server** | جهاز حقيقي في مركز بيانات | شركات كبيرة |
| **VPS** | Virtual Private Server — جزء من سيرفر كبير يخصك | **البداية المثالية** — Hetzner, DigitalOcean |
| **Dedicated Server** | سيرفر كامل لك فقط | حمل عالٍ |
| **Cloud Instance** | سيرفر من AWS/GCP/Azure | توسع تلقائي |

### VPS — ما الذي تشتريه فعلاً؟

عندما «تشتري سيرفر» بـ 5–10 دولار شهرياً، تشتري عادة **VPS**:

- نظام تشغيل (Linux — Ubuntu شائع)
- معالج (CPU) — عدد النوى
- ذاكرة (RAM) — 2GB, 4GB...
- تخزين (SSD) — 20GB, 40GB...
- عنوان IP
- اتصال إنترنت سريع

**مثال:** Hetzner CX22 — 2 vCPU, 4GB RAM, 40GB — ~€4/شهر.

### ماذا يعمل على السيرفر؟

```
السيرفر (Ubuntu Linux)
├── NestJS (تطبيق API) — المنفذ 3001
├── Next.js (واجهة) — المنفذ 3000
├── PostgreSQL (قاعدة بيانات) — المنفذ 5432
├── Nginx (يوجّه الطلبات من الإنترنت) — المنفذ 80/443
└── Caddy أو Certbot (شهادة HTTPS)
```

## 4. السحابة (Cloud)

### التعريف

شبكة ضخمة من السيرفرات تملكها شركات (Amazon, Google, Microsoft, Cloudflare...) وتأجر منها خدمات.

### مزودو السحابة الرئيسيون

| المزود | الخدمات | ملاحظة |
|--------|---------|--------|
| **AWS** (Amazon) | EC2, S3, RDS... | الأكبر — معقد للبداية |
| **Google Cloud (GCP)** | Compute, Cloud SQL... | GAS يعمل هنا |
| **Microsoft Azure** | VMs, SQL... | شائع في الشركات |
| **DigitalOcean** | Droplets, Managed DB | بسيط للمبتدئين |
| **Hetzner** | VPS رخيص | ممتاز للسعر |
| **Cloudflare** | CDN, R2, Workers | شبكة + تخزين |

### Cloud مقابل VPS

- **VPS:** سيرفر واحد تديره أنت (تثبيت، تحديث، أمان).
- **Cloud Managed:** الخدمة مُدارة (مثلاً قاعدة بيانات جاهزة — Supabase, Neon, RDS).

**للبداية:** VPS واحد + Postgres عليه، أو VPS للتطبيق + Postgres مُدار (Neon مجاني للتجارب).

## 5. الاستضافة (Hosting)

### التعريف

خدمة توفر لك مكاناً لتشغيل موقعك أو تطبيقك على الإنترنت.

### أنواع الاستضافة

| النوع | المناسب لـ | مثال |
|-------|-----------|------|
| **Shared Hosting** | مواقع WordPress بسيطة | **غير مناسب** لـ ERP |
| **VPS Hosting** | تطبيقات Node.js | Hetzner, DO |
| **Platform as a Service (PaaS)** | رفع كود بدون إدارة سيرفر | Railway, Render, Vercel (واجهة فقط) |
| **Serverless** | دوال صغيرة | AWS Lambda — لاحقاً |

**لـ TRADIVIA v2:** VPS أو PaaS مثل Railway للبداية السريعة.

## 6. النشر (Deploy / Deployment)

### التعريف

نقل التطبيق من جهازك (Local) إلى السيرفر (Production) ليستخدمه العملاء.

### خطوات النشر النموذجية

1. رفع الكود إلى GitHub
2. على السيرفر: `git pull` أو CI/CD تلقائي
3. `npm install` + `npm run build`
4. تشغيل التطبيق (PM2 أو systemd)
5. Nginx يوجّه الدومين للتطبيق
6. HTTPS يعمل

### Deploy vs Release

- **Deploy:** رفع نسخة على السيرفر.
- **Release:** إصدار رسمي للعملاء (قد يتضمن deploy).

### Rollback

الرجوع لنسخة سابقة إذا فشل التحديث.

## 7. الدومين (Domain)

### التعريف

اسم موقعك على الإنترنت — مثل `unigate.com`.

### أجزاء الدومين

```
https://app.finance.tradivia.com/api/incomes
│      │   │       │        │    │
│      │   │       │        │    └── المسار (Path)
│      │   │       │        └── الدومين الرئيسي
│      │   │       └── نطاق فرعي (Subdomain)
│      │   └── نطاق فرعي آخر
│      └── البروتوكول المشفر
└── HTTPS
```

### مصطلحات الدومين

| المصطلح | المعنى | مثال |
|---------|--------|------|
| **Domain** | الاسم الكامل | `tradivia.com` |
| **TLD** | الامتداد | `.com`, `.sy`, `.io` |
| **Subdomain** | جزء قبل الدومين | `app.`, `finance.` |
| **Registrar** | من تشتري منه | Namecheap, Cloudflare |
| **DNS** | نظام يحوّل الاسم لـ IP | A record, CNAME |

### DNS — كيف يعرف الإنترنت أين سيرفرك؟

```
المستخدم يكتب: finance.tradivia.com
        │
        ▼
DNS (مثل دليل الهاتف)
        │
        └── يُرجع: 185.xxx.xxx.xxx (IP السيرفر)
                │
                ▼
        السيرفر يستقبل الطلب
```

**سجلات DNS الشائعة:**

| السجل | الغرض |
|-------|--------|
| **A** | يوجّه الدومين إلى IP |
| **CNAME** | يوجّه subdomain إلى اسم آخر |
| **MX** | بريد إلكتروني |
| **TXT** | تحقق (مثل SPF للبريد) |

## 8. IP Address

### التعريف

عنوان رقمي فريد لكل جهاز على الإنترنت — مثل رقم هاتف السيرفر.

- **IPv4:** `192.168.1.1` (4 أرقام)
- **IPv6:** أطول — للمستقبل

### IP عام (Public) vs خاص (Private)

- **Public:** يصل من الإنترنت — IP السيرفر.
- **Private:** داخل شبكة محلية — `192.168.x.x` — جهازك في البيت.

### localhost

`127.0.0.1` — يشير لجهازك نفسه. `localhost:3000` = تطبيق على جهازك المنفذ 3000.

## 9. المنفذ (Port)

### التعريف

«باب» رقمي على السيرفر — كل خدمة تستخدم منفذاً.

| المنفذ | الخدمة الشائعة |
|--------|----------------|
| 80 | HTTP (بدون تشفير) |
| 443 | HTTPS (مشفر) |
| 3000 | Next.js تطوير |
| 3001 | NestJS API |
| 5432 | PostgreSQL |
| 22 | SSH (اتصال بالسيرفر) |

**في الإنتاج:** العميل يفتح 443 فقط — Nginx يوجّه داخلياً للمنفذ 3000.

## 10. HTTPS و SSL

### HTTP vs HTTPS

- **HTTP:** اتصال غير مشفر — غير آمن للبيانات المالية.
- **HTTPS:** اتصال مشفر — القفل في المتصفح.

### SSL / TLS

بروتوكول التشفير. **شهادة SSL** تثبت هوية موقعك.

### Let's Encrypt

جهة تمنح شهادات SSL **مجانية**. Caddy أو Certbot يجدّدها تلقائياً.

## 11. CDN (Content Delivery Network)

### التعريف

شبكة سيرفرات حول العالم تخزّن نسخاً من ملفاتك (صور، CSS, JS) لتصل للمستخدم أسرع.

**مثال:** Cloudflare CDN — مستخدم في دمشق يحمّل من سيرفر قريب.

**لـ ERP:** مفيد للواجهة والمرفقات — أقل أهمية في البداية.

## 12. قاعدة البيانات (Database)

### التعريف

نظام منظم لتخزين البيانات والبحث فيها والتحديث — بديل Google Sheets الاحترافي.

### لماذا لا Sheets للنظام الجديد؟

| المشكلة في Sheets | الحل في PostgreSQL |
|-------------------|-------------------|
| شخصان يعدّلان = تعارض | Transactions + locks |
| لا علاقات قوية بين الجداول | Foreign keys |
| بطء مع آلاف الصفوف | فهارس + SQL محسّن |
| لا قيود محاسبية صارمة | Constraints, triggers |
| صعب الفواتير والقيود | جداول مترابطة |

## 13. أنواع قواعد البيانات

### SQL (علائقية — Relational)

بيانات في **جداول** مترابطة — **PostgreSQL, MySQL, SQL Server**.

**مناسبة للمالية والERP — هذا اختيارك.**

### NoSQL

بيانات مرنة (مستندات، مفاتيح) — MongoDB, Redis.

**غير مناسبة كأساس لمحاسبة** — قد تُستخدم Redis للكاش لاحقاً.

### مقارنة سريعة

| | PostgreSQL | MySQL | SQLite | MongoDB |
|---|-----------|-------|--------|---------|
| ERP/مالية | ⭐⭐⭐ | ⭐⭐ | ⭐ | ⭐ |
| تزامن | ممتاز | جيد | ضعيف | معقد |
| التكلفة | مجاني | مجاني | مجاني | مجاني/مدفوع |

## 14. PostgreSQL — مفاهيم أساسية

### Database

قاعدة واحدة — مثل «ملف Excel كبير» يحتوي جداول كثيرة.

مثال: `tradivia_finance`

### Table (جدول)

مجموعة سجلات من نوع واحد — مثل Sheet واحد.

مثال: `incomes`, `employees`

### Row (صف / سجل / Record)

وحدة بيانات واحدة — صف في Sheet.

مثال: وارد رقم 1045 بمبلغ 5000$

### Column (عمود / حقل / Field)

خاصية واحدة — عمود في Sheet.

مثال: `amount`, `currency`, `employee_id`

### Primary Key (PK)

معرّف فريد لكل صف — عادة `id` (UUID أو رقم تسلسلي).

### Foreign Key (FK)

ربط بين جدولين — مثلاً `incomes.employee_id` → `employees.id`

### Index (فهرس)

يسرّع البحث — مثل فهرس في كتاب.

### Constraint (قيد)

قاعدة على البيانات — مثلاً `amount > 0`

### Schema

تصميم هيكل الجداول والعلاقات — مخطط البناء.

### Migration

تغيير هيكل القاعدة بشكل مُتحكم (إضافة جدول، عمود...) — Prisma Migrate.

### Seed

إدخال بيانات أولية (تجريبية) — موظف admin، إعدادات...

## 15. SQL — لغة قواعد البيانات

### التعريف

Structured Query Language — لغة للتحدث مع قاعدة البيانات.

### العمليات الأساسية (CRUD)

| العملية | SQL | المعنى |
|---------|-----|--------|
| Create | INSERT | إضافة سجل |
| Read | SELECT | قراءة |
| Update | UPDATE | تعديل |
| Delete | DELETE | حذف |

### أمثلة

```sql
-- قراءة كل الواردات لموظف
SELECT * FROM incomes WHERE employee_id = 'abc' AND deleted_at IS NULL;

-- مجموع مبلغ حسب العملة
SELECT currency, SUM(amount) FROM incomes GROUP BY currency;
```

**في مشروعك:** Prisma يكتب SQL نيابة عنك — لكن فهم SQL مهم للتقارير المعقدة.

## 16. ORM — Prisma

### التعريف

Object-Relational Mapping — طبقة بين كود TypeScript وقاعدة البيانات.

### لماذا Prisma؟

- تعرّف الجداول في `schema.prisma` بوضوح
- TypeScript يعرف أشكال البيانات تلقائياً
- Migrations منظمة
- AI يكتب Prisma بسهولة

### مثال

```prisma
model Income {
  id            String   @id @default(uuid())
  operationNumber Int
  amount        Decimal
  currency      String
  employeeId    String
  employee      Employee @relation(fields: [employeeId], references: [id])
  createdAt     DateTime @default(now())
}
```

## 17. معاملات قاعدة البيانات (Database Transaction)

### التعريف

مجموعة عمليات تُنفَّذ **كلها معاً أو لا شيء** — ACID.

### مثال مالي

فاتورة بيع:
1. إنشاء سجل في `invoices`
2. خصم من `stock_movements`
3. إنشاء `income`

إذا فشل (2) — يُلغى (1) و (3). **لا فاتورة بدون مخزون.**

### ACID

| الحرف | المعنى |
|-------|--------|
| **A** Atomicity | كل أو لا شيء |
| **C** Consistency | البيانات متسقة |
| **I** Isolation | العمليات المتزامنة لا تتداخل |
| **D** Durability | بعد الحفظ — البيانات دائمة |

**في GAS:** لا يوجد هذا — سبب أخطاء الأرصدة عند التزامن.

## 18. Soft Delete

### التعريف

«حذف» منطقي — السجل يبقى في القاعدة مع `deleted_at` أو `status = 'deleted'`.

**لماذا؟** العمليات المالية لا تُمحى فعلياً — للتدقيق والقانون.

## 19. Backup و Restore

### Backup (نسخة احتياطية)

نسخة من قاعدة البيانات لملف — `pg_dump` يومياً.

### Restore (استرجاع)

إعادة البيانات من النسخة عند كارثة.

### قاعدة ذهبية

**نسخة احتياطية بدون تجربة استرجاع = لا نسخة احتياطية.**

## 21. TypeScript

### التعريف

JavaScript + **أنواع بيانات** (types) — يكتشف الأخطاء قبل التشغيل.

```typescript
// JavaScript — خطأ يظهر عند التشغيل
function add(a, b) { return a + b; }
add("5", 3); // "53" — خطأ منطقي

// TypeScript — خطأ يظهر أثناء الكتابة

}
```

**لماذا لـ ERP؟** مبالغ مالية، IDs، تواريخ — الأنواع تمنع أخطاء مكلفة.

## 26. NestJS

finance/

### Controller vs Service

| | Controller | Service |
|---|-----------|---------|

## 27. API

### التعريف

### REST API

| Method | الغرض | مثال |
|--------|--------|------|
| GET | قراءة | `GET /api/incomes` |

### Endpoint

### Request / Response

  "currency": "USD"

### JSON

### مقارنة GAS

// GAS

fetch('/api/incomes', { method: 'POST', body: JSON.stringify(data) })

# الجزء الخامس: Git و GitHub

## 30. Git

### التعريف

نظام **تتبع التغييرات** في الكود — مثل «تاريخ زمني» لكل ملف.

### لماذا Git؟

- الرجوع لنسخة سابقة
- العمل على فروع بدون كسر الرئيسي
- التعاون مع الشريك
- ربط مع النشر التلقائي

### المفاهيم الأساسية

| المصطلح | المعنى |
|---------|--------|
| **Repository (Repo)** | مجلد المشروع + تاريخ Git |
| **Commit** | لقطة حفظ — «نقطة في الزمن» |
| **Branch** | خط تطوير منفصل |
| **main / master** | الفرع الرئيسي — الإنتاج |
| **Merge** | دمج فرع في آخر |
| **Clone** | نسخ repo من GitHub لجهازك |
| **Push** | رفع commits لـ GitHub |
| **Pull** | جلب تغييرات من GitHub |
| **Fetch** | جلب بدون دمج |
| **Remote** | نسخة على GitHub (`origin`) |
| **Staging** | `git add` — تحضير للـ commit |
| **Working Directory** | ملفاتك الحالية |
| **.gitignore** | ملفات لا تُرفع (node_modules, .env) |

### أوامر أساسية

```bash
git status          # ما الذي تغيّر؟
git add .           # إضافة كل التغييرات
git commit -m "وصف"
git push            # رفع لـ GitHub
git pull            # جلب من GitHub
git checkout -b feature/invoices   # فرع جديد
```

## 31. GitHub

### التعريف

منصة تستضيف مستودعات Git على الإنترنت + تعاون + Issues + Pull Requests.

### GitHub vs Git

- **Git:** الأداة على جهازك
- **GitHub:** الموقع الذي يحفظ المشروع سحابياً

### Pull Request (PR)

«اطلب من الشريك مراجعة تغييراتي قبل الدمج في main»

### Issue

تتبع مهمة أو خطأ — «إضافة فواتير الشراء»

### Fork

نسخة مستقلة من مشروع شخص آخر

# الجزء السادس: الأمان والمصادقة

## 33. Authentication (المصادقة)

**من أنت؟** — تسجيل الدخول.

- اسم مستخدم + كلمة مرور
- JWT token بعد النجاح

## 34. Authorization (الصلاحيات)

**ماذا تستطيع أن تفعل؟** — موظف vs مشرف.

## 35. JWT (JSON Web Token)

### التعريف

رمز مشفر يثبت أنك سجّلت دخولك — يُرسل مع كل طلب API.

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

**مقارنة GAS:** `session token` في Script Properties → JWT في النظام الجديد.

## 36. Session (جلسة)

فترة بين تسجيل الدخول والخروج — 8 ساعات مثلاً.

## 37. Hash و Salt

### Hash

تحويل كلمة المرور لنص لا يُعاد — `bcrypt`, `argon2`

### Salt

قيمة عشوائية تُضاف قبل التشفير — كل مستخدم salt مختلف.

**لا تخزّن كلمات المرور كنص** — خطأ شائع في GAS يجب إصلاحه.

## 38. Environment Variables (.env)

إعدادات سرية **خارج الكود**:

```env
DATABASE_URL=postgresql://...
JWT_SECRET=سر-طويل-عشوائي
```

**لا ترفع `.env` على GitHub أبداً.**

## 39. CORS

Cross-Origin Resource Sharing — من يستطيع استدعاء API من متصفح.

الواجهة على `localhost:3000` والـ API على `localhost:3001` — يحتاج إعداد CORS.

## 40. HTTPS

إلزامي في Production — تشفير كل الاتصال.

## 41. SQL Injection

هجوم عبر إدخال SQL في حقول — Prisma يحمي تلقائياً.

## 42. XSS

هجوم عبر حقن JavaScript — تعقيم المدخلات في الواجهة.

# الجزء العاشر: DevOps والعمليات

## 58. DevOps

جمع **التطوير (Dev)** و **العمليات (Ops)** — نشر، مراقبة، نسخ احتياطي.

## 59. CI/CD

### CI — Continuous Integration

كل push يشغّل اختبارات تلقائية.

### CD — Continuous Deployment

إذا نجحت الاختبارات — نشر تلقائي.

**أداة شائعة:** GitHub Actions

**للبداية:** نشر يدوي — CI/CD لاحقاً.

## 60. Docker

### التعريف

«حاوية» تشغّل تطبيقك بنفس البيئة في أي مكان.

```
صورة Docker (Image) → حاوية تعمل (Container)
```

**فائدة:** Postgres بنفس الإعداد على جهازك والسيرفر.

**للبداية:** يمكن تثبيت Postgres مباشرة بدون Docker.

## 61. Container

بيئة معزولة لتشغيل تطبيق — Docker container

## 62. Kubernetes (K8s)

إدارة آلاف الحاويات — **مبكر جداً** لمشروعك.

## 63. PM2

مدير عمليات لـ Node.js على السيرفر — يعيد تشغيل التطبيق إذا تعطل.

```bash
pm2 start dist/main.js --name api
pm2 startup
```

## 64. Nginx

خادم ويب يوجّه الطلبات:

```
الإنترنت → Nginx (443) → Next.js (3000) أو NestJS (3001)
```

## 65. Reverse Proxy

Nginx يستقبل من الخارج ويوجّه داخلياً — يخفي المنافذ الداخلية.

## 66. Load Balancer

يوزّع الحمل على عدة سيرفرات — عندما يكبر عدد المستخدمين.

## 67. SSH

الاتصال الآمن بالسيرفر من الطرفية:

```bash
ssh root@185.xxx.xxx.xxx
```

## 68. Firewall

جدار ناري — يفتح المنافذ الضرورية فقط (22, 80, 443).

## 69. Logs

سجلات ما يحدث — أخطاء، طلبات، مدة الاستجابة.

## 70. Monitoring

مراقبة صحة النظام — CPU, RAM, هل التطبيق يعمل؟

## 71. Sentry

خدمة تتبع أخطاء JavaScript في Production — يُرسل لك التفاصيل عند تعطل.

## 72. Uptime

نسبة وقت عمل النظام — 99.9% = ~8 ساعات توقف سنوياً.

## 73. Downtime

وقت التوقف — تجنبه بنسخ احتياطي ومراقبة.

# الجزء الثالث عشر: قرارات عملية — أسئلة شائعة

## 86. «أشتري سيرفر» — ماذا أفعل فعلاً؟

1. سجّل في Hetzner أو DigitalOcean
2. أنشئ VPS (Ubuntu 22.04, 2–4GB RAM)
3. اربط الدومين بـ IP السيرفر (DNS A record)
4. ثبّت Node, Postgres, Nginx, PM2
5. ارفع التطبيق
6. فعّل HTTPS
7. جدول نسخ احتياطي يومي

## 87. هل أحتاج دومين من اليوم الأول؟

- **التطوير:** لا — localhost يكفي
- **تسليم TRADIVIA:** نعم — يعطي احترافية

## 88. أين قاعدة البيانات؟

| الخيار | متى |
|--------|-----|
| Postgres على نفس VPS | بسيط، رخيص |
| Postgres مُدار (Neon, Supabase) | أسهل صيانة، نسخ احتياطي جاهز |
| Postgres على جهازك | تطوير فقط |

## 89. ما الفرق بين Vercel و VPS؟

- **Vercel:** ممتاز لـ Next.js — الواجهة فقط
- **VPS:** كل شيء (API + DB) — **تحتاجه لـ NestJS + Postgres**

يمكن: Vercel للواجهة + VPS للـ API — أو كل شيء على VPS.

## 90. كم يكلف التشغيل شهرياً؟ (تقدير بداية)

| البند | التكلفة |
|-------|---------|
| VPS | $5–15 |
| دومين | $10–15/سنة |
| R2 تخزين | مجاني تقريباً للبداية |
| **المجموع** | ~$10–20/شهر |
