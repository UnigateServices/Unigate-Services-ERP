# شبكة أمان دمج المالية (المرحلة F0)

سكربت يشغّل **سيناريو عمليات ثابتاً** على تطبيق المالية، ثم يسجّل كل الأرقام التي يحسبها النظام في ملف JSON. الغرض: أن نثبت أن نقل المالية إلى الأساس (المراحل F2 إلى F4) **لم يغيّر أي رقم**.

- `baseline/original.json`: الأرقام كما يحسبها تطبيق المالية الأصلي (`Reference/erp-finance`، commit `77ce653`). هذا الملف هو المرجع.
- `scenario.mjs`: السيناريو نفسه، ويعمل على أي نسخة من الـ API.

## ماذا يفعل السيناريو

كل التواريخ ثابتة (أيلول 2026)، فالنتيجة لا تتغير حسب يوم التشغيل.

1. أسعار صرف الليرة مقابل الدولار في أربعة أيام.
2. بيانات أساسية: مشروع، وبنك، وصاحب سلفة، وزبون، ومورد، ومستودع، ومنتج.
3. أرصدة افتتاحية لموظف المكتب الأول (دولار وليرة).
4. إيرادات ومصاريف وتحويل إلى البنك، من الموظف والمدير.
5. موافقات: الموظف يطلب تعديل إيراد (المشرف يوافق)، ويطلب حذف مصروف (المشرف يرفض).
6. صرافة: شراء دولار وبيع دولار.
7. سلفة: صرف، ومصروف من السلفة، واسترداد جزء.
8. فاتورة شراء مُرحَّلة مع دفعة، وفاتورة بيع مُرحَّلة مع خصم ودفعة جزئية.
9. التسجيل: الأرصدة، وميزان المراجعة (بالليرة وبالدولار)، وقائمة الدخل، والميزانية، والتدفقات النقدية، وحقوق الملكية، والقيود، ودليل الحسابات، والذمم وأعمارها، والفاتورتان، وكل العمليات، والموافقات، وما يراه كل دور (المراقب، والمشرف، والموظف).

قبل الحفظ تُحذف الأشياء التي تختلف بين تشغيلين، وهي ليست أرقاماً مالية: المعرّفات، وأوقات الإنشاء، والتاريخ داخل أرقام المراجع (`OUT-261023-002` تصبح `OUT-YYMMDD-002`)، وتاريخ اليوم.

## التشغيل

يحتاج قاعدة بيانات **جديدة**: بعد الـ migrations والـ seed، وقبل أي عملية.

```powershell
# 1. تطبيق المالية الأصلي على قاعدة فارغة (من Reference/erp-finance)
npx prisma migrate deploy --schema packages/database/prisma/schema.prisma
npm run db:seed
npm run dev:api

# 2. السيناريو (من جذر المستودع)
node tools/finance-baseline/scenario.mjs http://localhost:3001/api run.json

# 3. المقارنة: لا يجب أن يظهر أي فرق
git diff --no-index tools/finance-baseline/baseline/original.json run.json
```

## الاختبارات الموجودة في المالية

الملفات الخمسة `*.spec.ts` في `Reference/erp-finance/apps/api/src/finance/` تعمل بـ `npx tsx <الملف>`. الثلاثة التي انتقلت في F3a صارت `*.check.ts` في `uni-gate/apps/api/src/finance/` وتعمل ضمن `npm run test:api`. الخمسة ناجحة على النسخة الأصلية، بشرط أن يكون الـ API قد عمل مرة واحدة على القاعدة (اختبار المطابقة يحتاج دليل الحسابات الذي ينشئه الـ API).

## التشغيل على الـ API المدموج (من F3a)

- `baseline/f3a.json`: أرقام الدفعة F3a فقط (العملات والأسعار، والمشاريع والبنوك وأصحاب السلف، والأرصدة الافتتاحية، والأرصدة، والقيود ودليل الحسابات، والقيد الافتتاحي، والموافقات، وما يراه المراقب والمشرف والموظف). سُجّلت من التطبيق الأصلي بـ `SCENARIO_BATCH=f3a`.
- متغيرات السيناريو: `SCENARIO_TARGET` (`original` أو `merged`)، و`SCENARIO_BATCH` (`full` أو `f3a`)، و`SCENARIO_COMPANY` (رمز الشركة في المدموج، الافتراضي `scenario`)، و`SCENARIO_PASSWORD`، و`SCENARIO_ORIGIN`.
- في المدموج، تسجيل الدخول برمز الشركة واسم المستخدم (`manager`، `monitor`، `supervisor1`، `employee1`...)، ومسارات المالية تحت `/api/finance`، و`/employees` صارت `/finance/members`.

```powershell
# قاعدة uni-gate جديدة، ثم شركة السيناريو (من uni-gate/apps/api)
$env:SCENARIO_PASSWORD="..."; npx tsx scripts/seed-finance-scenario.ts
npm run dev:api

# من جذر المستودع
$env:SCENARIO_TARGET="merged"; $env:SCENARIO_BATCH="f3a"
node tools/finance-baseline/scenario.mjs http://localhost:3001/api run.json
git diff --no-index tools/finance-baseline/baseline/f3a.json run.json
```

## في المراحل القادمة

في كل دفعة من F3، يُشغَّل السيناريو نفسه على الـ API المدموج، ويجب أن يطابق `baseline/original.json` حرفياً. الفرق الوحيد المسموح هو طريقة تسجيل الدخول وأسماء المستخدمين (يتكيف معها السيناريو)، لا الأرقام.
